The spec covers several independent subsystems, so implementation is split into **sub-plans**. Each sub-plan ends with working, tested software and is written in full detail **just before it starts**, against the code that actually exists at that point (writing all of them up front would bake in guesses about code that does not exist yet).

**Execution rules for every sub-plan**
- Work on a feature branch per sub-plan (`feat/p1-foundation`, …), merge to `main` via PR when `pnpm check` is green.
- TDD: failing test → minimal code → passing test → commit.
- Any change to the design updates **both** spec files in the same commit.

## Carry-over from the P1 review

Items found in the P1 final review and deliberately deferred to a later sub-plan.

**P2 — Design system**
- [x] `ServerStatus` retry feedback: show progress via `isFetching` and announce status changes through a persistent live region.
- [x] Use `userEvent.setup()` in component tests instead of the direct `userEvent` API.
- [x] Split the web tsconfig (app vs node/config files) so `node` types do not leak into browser code.
- [x] Add an error boundary for i18n/bootstrap failures.
- [x] Localize the `index.html` meta description and keep `<html lang>` in sync with the active language.

**P3 — Accounts & clans** (must land before any session cookie exists)
- [ ] `/api/docs`: route-scoped helmet CSP (with a nonce) and a pinned Scalar CDN version, or disable the docs in production. Note: from P2 on, the site-wide CSP in `netlify.toml` also applies to `/api/docs` when it is opened through the Netlify domain, so open the docs on the Render URL.
- [ ] Strip/validate response bodies (send parsed data, or strict schemas + DTO mappers) so extra fields such as password hashes cannot leak.
- [ ] Type handler results against the declared response schemas.
- [ ] Stop handlers writing to `res` directly (or guard `headersSent`) and support cookies/headers in `HandlerResult`.
- [ ] Set `trust proxy` for Netlify/Render.
- [ ] `apiClient`: status-based fallback for unknown error codes, a JSON body option that sets `Content-Type`, 204/empty responses, pass the TanStack Query abort `signal`, broader `apiClient` tests.
- [ ] Route registry: reject or support Express 5 `*splat` / `{opt}` paths, and detect duplicates regardless of parameter names.
- [ ] Graceful shutdown and `listen` error handling.

**P8 — MVP deploy**
- [ ] Review env validation, including an upper bound for `PORT`.
- [ ] Coverage reporting in CI, if wanted.

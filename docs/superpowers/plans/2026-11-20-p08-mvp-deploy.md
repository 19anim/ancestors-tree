# P8 MVP Deploy Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The MVP is safe to put in front of the family: only Netlify's proxy can reach the API, production refuses to start with a missing setting, unexpected errors reach Sentry without personal data, and a sleeping Render server shows a "Waking up the server…" screen instead of an error page.

**Architecture:**
- **Settings.** `apps/api/src/config.ts` adds `PROXY_SIGNATURE_SECRET`, `SENTRY_DSN` and `RENDER_GIT_COMMIT`. In production `CLOUDINARY_FOLDER` and `PROXY_SIGNATURE_SECRET` join `APP_ORIGIN` and `TRUST_PROXY_HOPS` as required: "not set" is detected before the development default applies.
- **Signed proxy.** `netlify.toml` signs the `/api/*` rewrite. A small middleware (`apps/api/src/http/proxySignature.ts`) checks the `x-nf-sign` JWS with `node:crypto` only. It is mounted right after `trust proxy` and the request logger, and runs only when the secret is set. The request log gains `clientIp` (the address after `trust proxy`), and the `x-nf-sign` header is redacted from it.
- **Errors to Sentry, API.** The error handler calls an `ErrorReporter` for unexpected errors only (the ones answered `INTERNAL_ERROR`, 500). In production with a DSN, `server.ts` loads `@sentry/node` on demand and builds the reporter. One pure scrubber in `packages/shared` removes request data, breadcrumbs, extras, user details other than the id, and email addresses, for the API and the web alike.
- **Wake-up detection.** The API client feeds a small Zustand store (`apps/web/src/shared/lib/wake.ts`): a gateway error without the API's body, or a network error while online, sets `waking` at once. A request still pending after 4 s makes one raw `/api/health` probe with a 3 s timeout, and only a failed probe sets `waking`. The probe and the screen's polls use `fetch` directly, never `apiRequest`, so they can never feed the detection.
- **Wake-up screen.** `features/system/WakeUpScreen.tsx` is mounted once in `App`, beside the router, and portalled to `<body>`. While it shows, every other child of `<body>` is `inert` (a new `inertPage` helper). It polls `/api/health` every 3 s; on success it awaits `queryClient.invalidateQueries()` and closes. After 2 minutes it says the server did not wake up, with "Thử lại". `RequireAuth` waits instead of throwing to the route error page while the screen is up, and `useClanTree` reloads a tree whose load failed while the server slept.
- **Errors to Sentry, web.** `shared/lib/monitoring.ts` exposes `reportError`. It queues reports, and it catches early unhandled errors and rejections, until `shared/lib/sentryClient.ts`, a separate chunk, loads after the first render. It is a no-op outside production or without `VITE_SENTRY_DSN`. The app and route error boundaries report what they catch, and expected `ApiError`s are never reported. `@sentry/vite-plugin` runs only when `SENTRY_AUTH_TOKEN` is set: it builds `hidden` source maps, uploads them and deletes them before Netlify publishes.

**Tech Stack:** Express 5, pino and pino-http, `node:crypto`, Zod 4, `@sentry/node` 11, React 19, Zustand 5, TanStack Query v5, `@sentry/react` 11, `@sentry/vite-plugin` 11, Vite 8, Vitest with jsdom and fake timers, Playwright.

## Global Constraints

- **Spec.** §12 ("Behind proxies" and "Signed proxy"), §13.1 ("Render cold start" and "Sentry") and §16 of `docs/superpowers/specs/2026-11-11-ancestors-tree-design.md`. - **Binding values** (copied from the spec):
  - the slow-request threshold is **4 s**;
  - the quick check is `/api/health` with **a 3 s health timeout**;
  - the wake-up screen checks `/api/health` **every 3 s**;
  - after **2 minutes** it says the server did not wake up and offers "Try again" ("Thử lại");
  - a gateway error is **502/503/504 without the API's error body** (`{ "error": { "code": … } }`);
  - in production, **`GET /api/health` exempt** from the signature check, nothing else (`HEAD` is the same route in Express);
  - the token's claims: **`iss` `netlify`, `exp`** in the future (with the 30 s clock skew of Task 2);
  - a refused request answers **`FORBIDDEN` 403**, the standard error body;

```ts
import { createHmac, timingSafeEqual } from 'node:crypto';
import type { RequestHandler } from 'express';
import type { Logger } from 'pino';
import { AppError } from './AppError.ts';
import { maskUrl } from './logSerializers.ts';

/** Netlify's signed proxy adds it to every request it forwards (netlify.toml `signed`). */
export const PROXY_SIGNATURE_HEADER = 'x-nf-sign';

/**
 * How long after `exp` a token still counts. Netlify does not document the token's lifetime, and
 * Render can hold a request while the instance starts for as long as Netlify waits (26 s), so
 * 30 s covers that hold plus a few seconds of clock drift between the two hosts.
 */
export const CLOCK_SKEW_SECONDS = 30;

export type ProxySignatureFailure =
  | 'missing'
  | 'malformed'
  | 'algorithm'
  | 'signature'
  | 'issuer'
  | 'expired';

export type ProxySignatureResult =
  | { ok: true }
  | { ok: false; reason: ProxySignatureFailure; secondsPastExp?: number };

function decodeObject(part: string): Record<string, unknown> | undefined {
  try {
    const value: unknown = JSON.parse(Buffer.from(part, 'base64url').toString('utf8'));
    return typeof value === 'object' && value !== null && !Array.isArray(value)
      ? (value as Record<string, unknown>)
      : undefined;
  } catch {
    return undefined;
  }
}

/**
 * Checks Netlify's x-nf-sign token (a compact JWS, HMAC SHA-256) with node:crypto only
 * (spec §12): HS256, a signature made with the shared secret, `iss` "netlify" and an `exp` that
 * has not passed (with CLOCK_SKEW_SECONDS of slack).
 */
export function verifyProxySignature(
  token: string | undefined,
  secret: string,
  nowSeconds: number,
): ProxySignatureResult {
  if (token === undefined || token === '') return { ok: false, reason: 'missing' };
  const parts = token.split('.');
  if (parts.length !== 3) return { ok: false, reason: 'malformed' };
  const [headerPart = '', payloadPart = '', signaturePart = ''] = parts;

  const header = decodeObject(headerPart);
  if (header === undefined) return { ok: false, reason: 'malformed' };
  // Only HS256: the token never chooses the algorithm (no "none", no algorithm confusion).
  if (header.alg !== 'HS256') return { ok: false, reason: 'algorithm' };

  const expected = createHmac('sha256', secret).update(`${headerPart}.${payloadPart}`).digest();
  const given = Buffer.from(signaturePart, 'base64url');
  // Buffer.from skips characters outside base64url, so the text must survive a round trip.
  if (
    given.toString('base64url') !== signaturePart ||
    given.length !== expected.length ||
    !timingSafeEqual(given, expected)
  ) {
    return { ok: false, reason: 'signature' };
  }

  const payload = decodeObject(payloadPart);
  if (payload === undefined || typeof payload.exp !== 'number') {
    return { ok: false, reason: 'malformed' };
  }
  if (payload.iss !== 'netlify') return { ok: false, reason: 'issuer' };
  if (nowSeconds > payload.exp + CLOCK_SKEW_SECONDS) {
    return { ok: false, reason: 'expired', secondsPastExp: Math.round(nowSeconds - payload.exp) };
  }
  return { ok: true };
}

/** Render's health check and the uptime monitor call it without going through Netlify. */
function isHealthCheck(method: string, path: string): boolean {
  if (method !== 'GET' && method !== 'HEAD') return false;
  // Express routes ignore case and a trailing slash, so the exemption must too.
  return path.toLowerCase().replace(/\/+$/, '') === '/api/health';
}

export interface ProxySignatureCheckOptions {
  /** PROXY_SIGNATURE_SECRET, the same value as on Netlify. */
  secret: string;
  logger: Logger;
  /** Milliseconds since the epoch; tests pass a fixed clock. */
  now?: () => number;
}

/**
 * Refuses every request that did not come through Netlify's signed proxy, except the health
 * check (spec §12). Nobody can then call the Render URL directly with a forged
 * X-Forwarded-For, so the per-IP limits hold.
 */
export function createProxySignatureCheck({
  secret,
  logger,
  now = Date.now,
}: ProxySignatureCheckOptions): RequestHandler {
  return (req, _res, next) => {
    if (isHealthCheck(req.method, req.path)) {
      next();
      return;
    }
    const result = verifyProxySignature(
      req.get(PROXY_SIGNATURE_HEADER),
      secret,
      Math.floor(now() / 1000),
    );
    if (result.ok) {
      next();
      return;
    }
    // The reason only: never the header (a credential until it expires) or the secret.
    logger.warn(
      {
        reason: result.reason,
        ...(result.secondsPastExp === undefined ? {} : { secondsPastExp: result.secondsPastExp }),
        method: req.method,
        path: maskUrl(req.path),
        clientIp: req.ip,
      },
      'Refused a request that did not come through the Netlify proxy',
    );
    next(new AppError('FORBIDDEN', 'Requests must come through the web app'));
  };
}
```

```ts
/** What an email address becomes in an error report (spec §13.1). */
export const REDACTED_EMAIL = '[email]';

const EMAIL = /[\w.+-]+@[\w-]+(\.[\w-]+)+/g;

export function redactEmails(text: string): string {
  return text.replace(EMAIL, REDACTED_EMAIL);
}

/**
 * The parts of a Sentry event the scrubber reads or removes. Structural, so `shared` does not
 * depend on an SDK: both @sentry/node and @sentry/react events fit it.
 */
export interface ScrubbableEvent {
  message?: string;
  exception?: { values?: { value?: string }[] };
  request?: unknown;
  user?: { id?: string | number };
  breadcrumbs?: unknown;
  extra?: unknown;
}

/**
 * No personal data leaves the app (spec §13.1): request data (body, cookies, headers, query
 * string), breadcrumbs (URLs and console text) and extras are dropped, the user keeps only an
 * id, and email addresses in the message and the exception values are redacted.
 */
export function scrubErrorEvent<E extends ScrubbableEvent>(event: E): E {
  const source: ScrubbableEvent = event;
  const {
    request: _request,
    breadcrumbs: _breadcrumbs,
    extra: _extra,
    user,
    ...rest
  } = source;
  const scrubbed: ScrubbableEvent = { ...rest };
  if (user?.id !== undefined) scrubbed.user = { id: user.id };
  if (rest.message !== undefined) scrubbed.message = redactEmails(rest.message);
  if (rest.exception?.values !== undefined) {
    scrubbed.exception = {
      ...rest.exception,
      values: rest.exception.values.map((value) =>
        value.value === undefined ? value : { ...value, value: redactEmails(value.value) },
      ),
    };
  }
  return scrubbed as E;
}
```

```ts
import { scrubErrorEvent } from '@ancestors-tree/shared';
import type * as SentryNode from '@sentry/node';
import type { ErrorReporter } from './reporter.ts';

/** The part of @sentry/node this module uses; tests pass a fake, so they never load the SDK. */
export type SentryNodeApi = Pick<
  typeof SentryNode,
  | 'init'
  | 'captureException'
  | 'eventFiltersIntegration'
  | 'functionToStringIntegration'
  | 'linkedErrorsIntegration'
  | 'dedupeIntegration'
  | 'onUncaughtExceptionIntegration'
  | 'onUnhandledRejectionIntegration'
  | 'contextLinesIntegration'
  | 'nodeContextIntegration'
>;

export interface SentrySettings {
  /** SENTRY_DSN of the Node project. */
  dsn: string;
  /** releaseOf(config): the commit Render deployed. */
  release: string;
}

/**
 * Errors only, and no personal data (spec §13.1). `tracesSampleRate` stays unset (no tracing,
 * so the free quota goes to errors). The default integrations are off: no HTTP or console
 * breadcrumbs, no request data, no local variables. Express is not instrumented
 * (`enableRuntimeChannelInjection: false`): the error handler reports explicitly.
 */
export function sentryOptions(settings: SentrySettings, sdk: SentryNodeApi): SentryNode.NodeOptions {
  return {
    dsn: settings.dsn,
    release: settings.release,
    environment: 'production',
    defaultIntegrations: false,
    integrations: [
      sdk.eventFiltersIntegration(),
      sdk.functionToStringIntegration(),
      sdk.linkedErrorsIntegration(),
      sdk.dedupeIntegration(),
      sdk.onUncaughtExceptionIntegration(),
      sdk.onUnhandledRejectionIntegration(),
      sdk.contextLinesIntegration(),
      sdk.nodeContextIntegration(),
    ],
    enableRuntimeChannelInjection: false,
    // SDK 11's replacement for sendDefaultPii: false.
    dataCollection: {
      userInfo: false,
      cookies: false,
      httpHeaders: false,
      httpBodies: [],
      urlQueryParams: false,
      stackFrameVariables: false,
      databaseQueryData: false,
      queues: false,
    },
    beforeSend: (event) => scrubErrorEvent(event),
    beforeBreadcrumb: () => null,
  };
}

/**
 * Loads the SDK on demand (production with a DSN only), starts it and returns the reporter the
 * error handler calls.
 */
export async function createSentryReporter(
  settings: SentrySettings,
  load: () => Promise<SentryNodeApi> = () => import('@sentry/node'),
): Promise<ErrorReporter> {
  const sdk = await load();
  sdk.init(sentryOptions(settings, sdk));
  return {
    captureException(error, { userId }) {
      sdk.captureException(error, userId === undefined ? undefined : { user: { id: userId } });
    },
  };
}
```

```ts
import { create } from 'zustand';

/** A request still waiting after this long makes one quick health check (spec §13.1). */
export const SLOW_REQUEST_MS = 4_000;
/** The quick check, and each check of the wake-up screen, gives up after this long. */
export const HEALTH_TIMEOUT_MS = 3_000;
/** How often the wake-up screen checks the server. */
export const POLL_INTERVAL_MS = 3_000;
/** After this long the wake-up screen says the server did not wake up. */
export const GIVE_UP_MS = 2 * 60_000;

const GATEWAY_STATUSES = new Set([502, 503, 504]);

export type WakePhase = 'awake' | 'waking' | 'failed';

export interface WakeState {
  phase: WakePhase;
  /** Counts the server's returns after the wake-up screen; loaders outside TanStack Query watch it. */
  recoveries: number;
}

export const useWakeStore = create<WakeState>()(() => ({ phase: 'awake', recoveries: 0 }));

/** The API's own error body `{ error: { code } }`, even with a code this client does not know. */
export function hasApiErrorBody(payload: unknown): boolean {
  if (typeof payload !== 'object' || payload === null) return false;
  const error = (payload as { error?: unknown }).error;
  return (
    typeof error === 'object' &&
    error !== null &&
    typeof (error as { code?: unknown }).code === 'string'
  );
}

/**
 * Whether a failed request means the server may be asleep (spec §13.1): a gateway error (502,
 * 503 or 504) whose body is not the API's own, or no answer at all (status 0) while the
 * browser is online. Offline, the pending queue keeps the edits; it is not a sleeping server.
 */
export function isWakeSignal(status: number, payload: unknown, online: boolean): boolean {
  if (status === 0) return online;
  return GATEWAY_STATUSES.has(status) && !hasApiErrorBody(payload);
}

export function startWaking(): void {
  if (useWakeStore.getState().phase === 'awake') useWakeStore.setState({ phase: 'waking' });
}

export function wakeFailed(): void {
  if (useWakeStore.getState().phase === 'waking') useWakeStore.setState({ phase: 'failed' });
}

export function retryWaking(): void {
  if (useWakeStore.getState().phase === 'failed') useWakeStore.setState({ phase: 'waking' });
}

export function serverAwake(): void {
  useWakeStore.setState((state) => ({ phase: 'awake', recoveries: state.recoveries + 1 }));
}

/** apiRequest calls it for every failed request: status 0 when nothing answered. */
export function noteFailedRequest(status: number, payload: unknown): void {
  if (isWakeSignal(status, payload, navigator.onLine)) startWaking();
}

/**
 * One GET /api/health with its own timeout; true when the server answers 2xx. It calls fetch
 * directly, never apiRequest, so it can never feed the detection it serves.
 */
export async function checkHealth(timeoutMs = HEALTH_TIMEOUT_MS): Promise<boolean> {
  const controller = new AbortController();
  const timer = setTimeout(() => controller.abort(), timeoutMs);
  try {
    const response = await fetch('/api/health', {
      headers: { Accept: 'application/json' },
      cache: 'no-store',
      signal: controller.signal,
    });
    return response.ok;
  } catch {
    return false;
  } finally {
    clearTimeout(timer);
  }
}

/** One quick check at a time, however many requests are slow together. */
let probing = false;

/**
 * apiRequest calls it as a request starts, and the returned function as it ends. A request
 * still waiting after SLOW_REQUEST_MS makes one health check; only a check that fails or times
 * out shows the wake-up screen, so a slow request on an awake server never does.
 */
export function watchSlowRequest(): () => void {
  const timer = setTimeout(() => {
    if (probing || useWakeStore.getState().phase !== 'awake') return;
    probing = true;
    void checkHealth().then((ok) => {
      probing = false;
      if (!ok) startWaking();
    });
  }, SLOW_REQUEST_MS);
  return () => clearTimeout(timer);
}

export interface WakeCycleOptions {
  check: () => Promise<boolean>;
  /** The server answered: refetch, then leave the screen. */
  onAwake: () => Promise<void>;
  /** GIVE_UP_MS passed without an answer. */
  onGiveUp: () => void;
}

/**
 * The wake-up screen's loop: a check at once, then every POLL_INTERVAL_MS (never two at a time),
 * until one succeeds or GIVE_UP_MS passes. Returns the cleanup.
 */
export function runWakeCycle({ check, onAwake, onGiveUp }: WakeCycleOptions): () => void {
  let stopped = false;
  let checking = false;
  const stop = () => {
    stopped = true;
    clearInterval(interval);
    clearTimeout(giveUp);
  };
  const tick = async () => {
    if (stopped || checking) return;
    checking = true;
    const ok = await check();
    checking = false;
    if (stopped || !ok) return;
    stop();
    await onAwake();
  };
  const interval = setInterval(() => void tick(), POLL_INTERVAL_MS);
  const giveUp = setTimeout(() => {
    stop();
    onGiveUp();
  }, GIVE_UP_MS);
  void tick();
  return stop;
}

export function resetWakeForTests(): void {
  useWakeStore.setState({ phase: 'awake', recoveries: 0 });
  probing = false;
}
```

**Radix modals.** While a Radix modal is open, Radix sets `pointer-events: none` on `<body>`. The screen therefore carries `pointer-events-auto`, so "Thử lại" stays clickable.

`apps/web/src/shared/ui/inertPage.ts`:

```ts
/**
 * Makes every child of <body> but `keep` inert, dialogs and portals included, also those that
 * mount later; returns the undo, which removes only what this call set. For a screen that blocks
 * the whole app (the wake-up screen). A side sheet uses inertOthers, which keeps live regions
 * and dialogs operable.
 */
export function inertPage(keep: Element): () => void {
  const made = new Set<Element>();
  const hide = (element: Element) => {
    if (element === keep || element.contains(keep)) return;
    if (element.tagName === 'SCRIPT' || element.hasAttribute('inert')) return;
    element.setAttribute('inert', '');
    made.add(element);
  };
  for (const child of Array.from(document.body.children)) hide(child);

  const observer = new MutationObserver((records) => {
    for (const record of records) {
      for (const node of Array.from(record.addedNodes)) {
        if (node instanceof Element && node.parentElement === document.body) hide(node);
      }
    }
  });
  observer.observe(document.body, { childList: true });

  return () => {
    observer.disconnect();
    for (const element of made) element.removeAttribute('inert');
  };
}
```

```tsx
import { useQueryClient } from '@tanstack/react-query';
import { useEffect, useId, useRef } from 'react';
import { createPortal } from 'react-dom';
import { useTranslation } from 'react-i18next';
import { cn } from '../../shared/lib/cn';
import {
  checkHealth,
  retryWaking,
  runWakeCycle,
  serverAwake,
  useWakeStore,
  wakeFailed,
  type WakePhase,
} from '../../shared/lib/wake';
import { Button, inertPage, tapeColor } from '../../shared/ui';

/**
 * The full-page "Waking up the server…" screen (spec §13.1). Mounted once, beside the router;
 * portalled to <body> so it covers dialogs too.
 */
export function WakeUpScreen() {
  const phase = useWakeStore((state) => state.phase);
  if (phase === 'awake') return null;
  return createPortal(<WakeUpPanel phase={phase} />, document.body);
}

function WakeUpPanel({ phase }: { phase: Exclude<WakePhase, 'awake'> }) {
  const { t } = useTranslation();
  const queryClient = useQueryClient();
  const headingId = useId();
  const rootRef = useRef<HTMLDivElement>(null);
  const headingRef = useRef<HTMLHeadingElement>(null);

  // The app stays mounted underneath, inert, so drafts and pending changes are kept. Focus
  // moves to the heading and goes back where it was afterwards.
  useEffect(() => {
    const root = rootRef.current;
    if (root === null) return;
    const previous = document.activeElement instanceof HTMLElement ? document.activeElement : null;
    const undo = inertPage(root);
    headingRef.current?.focus();
    return () => {
      undo();
      if (previous?.isConnected && previous.closest('[inert]') === null) previous.focus();
    };
  }, []);

  useEffect(() => {
    if (phase !== 'waking') return;
    return runWakeCycle({
      check: () => checkHealth(),
      onAwake: async () => {
        // Refetch before leaving: RequireAuth waits while the phase is not "awake".
        await queryClient.invalidateQueries();
        serverAwake();
      },
      onGiveUp: wakeFailed,
    });
  }, [phase, queryClient]);

  const failed = phase === 'failed';
  return (
    <div
      ref={rootRef}
      role="dialog"
      aria-modal="true"
      aria-labelledby={headingId}
      // pointer-events-auto: a Radix modal underneath sets pointer-events: none on <body>.
      className="board-grid pointer-events-auto fixed inset-0 z-60 flex items-center justify-center overflow-y-auto p-6"
    >
      <div className="relative w-full max-w-md rounded-photo border border-line bg-surface px-6 pt-9 pb-6 text-ink">
        <span
          aria-hidden="true"
          className="absolute -top-3 left-1/2 h-6 w-28 -translate-x-1/2 -rotate-2 opacity-90"
          style={{ backgroundColor: tapeColor('progenitor') }}
        />
        <h1 ref={headingRef} id={headingId} tabIndex={-1} className="text-2xl">
          {t(failed ? 'system.wakeUp.failedTitle' : 'system.wakeUp.title')}
        </h1>
        <p className="mt-3 text-ink-muted">{t('system.wakeUp.body')}</p>
        <div className="mt-5 flex items-center gap-3">
          <span
            aria-hidden="true"
            className={cn('size-2 shrink-0 rounded-full', failed ? 'bg-stamp' : 'bg-line-strong')}
          />
          {/* One persistent live region: the change to "did not wake up" is announced. */}
          <p role="status" aria-live="polite" className="text-sm text-ink-muted">
            {t(failed ? 'system.wakeUp.failed' : 'system.wakeUp.waiting')}
          </p>
        </div>
        {failed ? (
          <Button
            className="mt-5"
            onClick={() => {
              retryWaking();
              headingRef.current?.focus();
            }}
          >
            {t('system.wakeUp.retry')}
          </Button>
        ) : null}
      </div>
    </div>
  );
}
```

```ts
/** Extra tags sent with a report, such as which error boundary caught it. */
export type ReportContext = Readonly<Record<string, string>>;

/** What the lazily loaded SDK offers the rest of the app. */
export interface MonitoringClient {
  captureException(error: unknown, context?: ReportContext): void;
  setUserId(id: string | null): void;
}

export interface MonitoringSettings {
  /** Production builds only (import.meta.env.PROD). */
  enabled: boolean;
  /** VITE_SENTRY_DSN; monitoring is off without it. */
  dsn: string | undefined;
  /** The commit (Netlify's COMMIT_REF at build time). */
  release: string;
  /** Netlify's deploy context (production, deploy-preview…). */
  environment: string;
}

export interface SdkSettings {
  dsn: string;
  release: string;
  environment: string;
}

export type LoadMonitoringClient = (settings: SdkSettings) => Promise<MonitoringClient>;

/** Reports kept until the SDK has loaded; any more in the first seconds are dropped. */
export const MAX_QUEUED_REPORTS = 20;

interface QueuedReport {
  error: unknown;
  context: ReportContext | undefined;
}

let sdkSettings: SdkSettings | null = null;
let client: MonitoringClient | null = null;
let queue: QueuedReport[] = [];
let userId: string | null = null;
let removeEarlyListeners: (() => void) | null = null;

/**
 * Expected failures are not bugs (spec §13.1): API errors carry a known code (4xx, offline, a
 * sleeping server), and the server reports its own 5xx. Only an answer the client cannot read
 * (INVALID_RESPONSE) points at a bug here.
 */
export function shouldReport(error: unknown): boolean {
  return !(error instanceof ApiError) || error.code === 'INVALID_RESPONSE';
}

/** Sends a caught error to Sentry; a no-op outside production or without a DSN. */
export function reportError(error: unknown, context?: ReportContext): void {
  if (sdkSettings === null || !shouldReport(error)) return;
  if (client !== null) client.captureException(error, context);
  else if (queue.length < MAX_QUEUED_REPORTS) queue.push({ error, context });
}

/** The signed-in user's id, the only user detail a report carries; null when signed out. */
export function identifyUser(id: string | null): void {
  userId = id;
  client?.setUserId(id);
}

function stopEarlyListeners(): void {
  removeEarlyListeners?.();
  removeEarlyListeners = null;
}

/**
 * Before the first render: decides whether monitoring is on, and catches unhandled errors and
 * rejections until the SDK, which has its own handlers, has loaded. Returns whether it is on.
 */
export function startMonitoring(settings: MonitoringSettings): boolean {
  if (!settings.enabled || !settings.dsn) return false;
  sdkSettings = { dsn: settings.dsn, release: settings.release, environment: settings.environment };
  const onError = (event: ErrorEvent) => reportError(event.error ?? new Error(event.message));
  const onRejection = (event: PromiseRejectionEvent) => reportError(event.reason);
  window.addEventListener('error', onError);
  window.addEventListener('unhandledrejection', onRejection);
  removeEarlyListeners = () => {
    window.removeEventListener('error', onError);
    window.removeEventListener('unhandledrejection', onRejection);
  };
  return true;
}

const loadSentryClient: LoadMonitoringClient = async (settings) => {
  // A separate chunk: the SDK never weighs on the first render.
  const { createSentryClient } = await import('./sentryClient');
  return createSentryClient(settings);
};

/** Loads the SDK, then sends what was queued. A failed load turns monitoring off. */
export async function loadMonitoring(load: LoadMonitoringClient = loadSentryClient): Promise<void> {
  if (sdkSettings === null || client !== null) return;
  try {
    const loaded = await load(sdkSettings);
    stopEarlyListeners();
    client = loaded;
    loaded.setUserId(userId);
    for (const report of queue) loaded.captureException(report.error, report.context);
    queue = [];
  } catch (error) {
    console.error(error);
    stopEarlyListeners();
    sdkSettings = null;
    queue = [];
  }
}

/** After the first render, when the browser is idle. */
export function loadMonitoringWhenIdle(): void {
  const start = () => void loadMonitoring();
  if (typeof window.requestIdleCallback === 'function') {
    window.requestIdleCallback(start, { timeout: 5_000 });
  } else {
    window.setTimeout(start, 2_000);
  }
}

export function resetMonitoringForTests(): void {
  stopEarlyListeners();
  sdkSettings = null;
  client = null;
  queue = [];
  userId = null;
}
```

```ts
import * as Sentry from '@sentry/react';
import { shouldReport, type MonitoringClient, type SdkSettings } from './monitoring';

/**
 * Loaded on demand by monitoring.ts after the first render, so the SDK stays out of the main
 * bundle. Errors only (spec §13.1): tracesSampleRate stays unset (no tracing), and the default
 * integrations are off (no sessions, no breadcrumbs with URLs or console text, no request
 * context). Every event is scrubbed of personal data.
 */
export function createSentryClient(settings: SdkSettings): MonitoringClient {
  Sentry.init({
    dsn: settings.dsn,
    release: settings.release,
    environment: settings.environment,
    defaultIntegrations: false,
    integrations: [
      Sentry.eventFiltersIntegration(),
      Sentry.functionToStringIntegration(),
      Sentry.browserApiErrorsIntegration(),
      Sentry.globalHandlersIntegration(),
      Sentry.linkedErrorsIntegration(),
      Sentry.dedupeIntegration(),
    ],
    // SDK 11's replacement for sendDefaultPii: false.
    dataCollection: {
      userInfo: false,
      cookies: false,
      httpHeaders: false,
      httpBodies: [],
      urlQueryParams: false,
      stackFrameVariables: false,
    },
    // An unhandled rejection of an expected API error is not a bug either.
    beforeSend: (event, hint) =>
      shouldReport(hint.originalException) ? scrubErrorEvent(event) : null,
    beforeBreadcrumb: () => null,
  });
  return {
    captureException: (error, context) => {
      Sentry.captureException(error, context === undefined ? undefined : { tags: context });
    },
    setUserId: (id) => {
      Sentry.setUser(id === null ? null : { id });
    },
  };
```

Write `docs/adr/0013-signed-proxy-and-error-reporting.md`:

```markdown
# ADR 0013: Signed proxy and error reporting

- Status: Accepted
- Date: 2026-11-20

## Context

The MVP goes in front of real families (P8). Three problems were left open.

- The Render URL is public. A caller who skips Netlify can send any `X-Forwarded-For`, pick a new IP for every request and get past the per-IP rate limits (spec §12).
- A missing production setting fell back to a development default without a word: production photos went to the dev Cloudinary folder.
- Nobody sees the errors that real users hit. The free Sentry plan allows 5,000 errors a month, and the app holds family data that must not leave it (spec §13.1).

A sleeping Render instance takes 30–60 s to wake up. Netlify's proxy gives up after 26 s with a gateway error, which is not a bug to report.

## Decision

**Netlify signs, the API checks.** The `/api/*` rewrite in `netlify.toml` has `signed = "PROXY_SIGNATURE_SECRET"`, so Netlify sends `x-nf-sign` (a JWS, HS256) with every proxied request. A middleware checks it with `node:crypto` only. It requires `alg` HS256, an HMAC compared with `timingSafeEqual`, `iss` "netlify", and an `exp` no more than 30 s in the past: Render can hold a request for the 26 s that Netlify waits, plus some clock drift. It runs right after `trust proxy` and the request logger, before the rate limits and the routes. `GET`/`HEAD /api/health` are exempt for Render's health check and the uptime monitor. A refused request answers `FORBIDDEN` (403), and the warning log holds the reason only. The header is redacted from the request log, which now records `clientIp`, the address after `trust proxy`.

**No development defaults in production.** `CLOUDINARY_FOLDER` and `PROXY_SIGNATURE_SECRET` join `APP_ORIGIN` and `TRUST_PROXY_HOPS`: without them the API refuses to start, so Render keeps the previous deploy.

**Errors to Sentry, errors only, no personal data.** Both sides use SDK 11, with the default integrations off, no tracing and `dataCollection` off (SDK 11's replacement for `sendDefaultPii`). One scrubber in `shared` drops request data, breadcrumbs, extras and user details except the id, and redacts email addresses. The release is the commit.
- The API loads `@sentry/node` only in production with `SENTRY_DSN`. The error handler reports unexpected errors (answered 500) explicitly; known codes are never sent.
- The web loads `@sentry/react` in its own chunk after the first render. Before that, `reportError` queues reports and catches unhandled errors. The error boundaries report what they catch. Expected API errors, router 404s and the sleeping server are never sent.
- With `SENTRY_AUTH_TOKEN` the Netlify build makes `hidden` source maps, uploads them and deletes them before publishing.

**A gateway error is a sleeping server, not a bug.** The API client turns it into the wake-up screen (spec §13.1), not a report.

## Alternatives considered

- **Allow only Netlify's IP addresses.** Netlify does not publish a stable list of egress addresses.
- **A static shared header.** A fixed secret that never expires: anyone who saw one request could replay it forever, and it would sit in every log.
- **`jose` for the token.** It is already a dependency, and `jwtVerify` with `algorithms: ['HS256']` would work. The check is one fixed algorithm and two claims, about 30 lines of `node:crypto`, with nothing to configure wrongly.
- **Sentry's default integrations and tracing.** They use the free quota for spans, and they send URLs, headers and breadcrumbs that can hold names, emails and invite tokens.
- **The web SDK in the main bundle.** It costs every visitor tens of kilobytes before the first render, to report errors that are rare.

## Consequences

- Calling the Render URL directly answers 403, except `/api/health`. Local development and the e2e API have no secret, so they skip the check.
- `PROXY_SIGNATURE_SECRET` lives in two places (Netlify and Render), and they must match. Changing it needs a new value on both, then a Netlify deploy and a Render deploy; until both are done, requests fail with 403.
- Netlify does not document the token's lifetime. A refused `expired` request logs `secondsPastExp`, so the skew can be checked against the logs.
- Sentry events carry no request context; the stack trace, the release, the boundary tag and the user id must be enough.
- `@sentry/node` 11 brings `@sentry/bundler-plugins` and the `sentry` CLI into the API's production install, where they are unused.
```

````markdown
| `SENTRY_DSN` | Render | optional: without it nothing is sent | the DSN of the Sentry **Node** project |
| `VITE_SENTRY_DSN` | Netlify | optional | the DSN of the Sentry **React** project; it ends up in the browser bundle, which is expected (a DSN only allows sending events) |
| `SENTRY_AUTH_TOKEN` | Netlify | optional: without it there are no source maps | lets the build upload source maps |
| `SENTRY_ORG`, `SENTRY_PROJECT` | Netlify | with the token | the organization slug and the React project slug |
| `CLOUDINARY_FOLDER` | Render (from `render.yaml`) | now required in production | `ancestors-tree/prod` |
| `RENDER_GIT_COMMIT`, `COMMIT_REF` | set by Render and Netlify | nothing to do | the commit, used as the Sentry release |

### Step 1: generate the proxy secret

Run `openssl rand -base64 48` once and keep the output in your password manager. The same value goes to Render and Netlify. Never commit it, and never put it in `apps/api/.env`: locally the Vite proxy does not sign, so with a value every request except `/api/health` would answer 403.

### Step 2: Sentry

1. Sign in at https://sentry.io (the free Developer plan is enough).
2. **Projects → Create Project → React**, name it `ancestors-tree-web`. Skip the setup wizard; the code is already in place.
3. **Projects → Create Project → Node.js** (or Express), name it `ancestors-tree-api`.
4. For each project, copy its DSN from **Settings → Projects → (project) → Client Keys (DSN)**: `<your DSN from Sentry → Project settings → Client Keys>`. The React one is for Netlify and the Node one is for Render.
5. Note the organization slug (**Settings → Organization → General Settings → Organization Slug**) and the React project's slug (`ancestors-tree-web`).
6. Create the build token. Use **Settings → Developer Settings → Organization Tokens → Create New Token**, named `netlify-source-maps`. An organization token has the release and source map rights the Vite plugin needs. If you use a personal token instead (**User settings → Personal Tokens**), give it **Project: Read & Write** and **Release: Admin**. Copy it once: `<your organization token from Sentry → Settings → Organization Tokens>`.
7. Recommended: in **Settings → Security & Privacy**, turn on **Prevent Storing of IP Addresses** and keep **Data Scrubber** and **Use Default Scrubbers** on. The app already sends no personal data; this is a second net on Sentry's side.

### Step 3: Render

1. **Blueprints → (the blueprint) → Manual sync**, so `render.yaml`'s `CLOUDINARY_FOLDER=ancestors-tree/prod` and the two new `sync: false` keys are applied.
2. **ancestors-tree-api → Environment → Add Environment Variable**:
   - `PROXY_SIGNATURE_SECRET` = the value from step 1;
   - `SENTRY_DSN` = `<your DSN from Sentry → Project settings → Client Keys>` of the **Node** project.
3. Check that `CLOUDINARY_FOLDER` shows `ancestors-tree/prod`.
4. Choose **Save only**: the merge deploys the new code. The API that runs now ignores these variables.

### Step 4: Netlify

**Project configuration → Environment variables → Add a variable → Add a single variable**, once per variable:

| Key | Value | Scopes | Deploy contexts |
| --- | --- | --- | --- |
| `PROXY_SIGNATURE_SECRET` | the value from step 1 | must include **Runtime** (signed proxy redirects read it at runtime) | same value for all |
| `VITE_SENTRY_DSN` | `<your DSN from Sentry → Project settings → Client Keys>` of the **React** project | **Builds** | Production only, so previews send nothing |
| `SENTRY_AUTH_TOKEN` | the token from step 2.6; tick **Contains secret values** if offered | **Builds** | Production only |
| `SENTRY_ORG` | the organization slug | **Builds** | Production only |
| `SENTRY_PROJECT` | `ancestors-tree-web` | **Builds** | Production only |

On the free plan Netlify does not offer scopes: every variable gets all of them, which covers both Runtime and Builds. `PROXY_SIGNATURE_SECRET` is then visible to the build too, but Vite puts only `VITE_*` variables in the bundle, so it never reaches the browser.

### Step 5: deploy order

1. Steps 1 to 4 come **before** the merge.
2. Merge the P8 pull request. Netlify builds at once, publishes the new web app and starts signing `/api/*`. The old API ignores the header, so nothing breaks in the meantime.
3. Render deploys after CI passes. With the variables set, the new API starts and checks every signature. If a required variable is missing, the new API stops at boot with a message that names the variable (never its value), the health check fails, and Render keeps the old API running. Add the variable, then **Manual Deploy → Deploy latest commit**.
4. If every page fails after Render's deploy and the logs show `Refused a request that did not come through the Netlify proxy` with `reason: "missing"` or `"signature"`, the two values differ, or Netlify's variable lacks the Runtime scope. Fix it on Netlify, then **Deploys → Trigger deploy → Deploy project** so the redirect picks it up. While you fix it, **Render → Events → (the previous deploy) → Rollback** brings the old API back.

### Step 6: verify

1. **Visitor IP.** Open the site, then **Render → Logs**. The `request completed` lines of your visit carry `clientIp`, which must be your own public IP (your router or any "what is my IP" page shows it). If it is a Netlify or Render address, `TRUST_PROXY_HOPS` is wrong.
2. **The signature.**
   - `curl -i https://ancestors-tree-api.onrender.com/api/clans` answers `403` with `"code":"FORBIDDEN"`.
   - `curl -i https://ancestors-tree-api.onrender.com/api/health` answers `200`.
   - `curl -i https://ancestorstree.netlify.app/api/me` answers `401` (signed out), not 403: the proxy signs.
3. **Sentry, web.** Open the site, then the browser's developer console, and run `setTimeout(() => { throw new Error('P8 Sentry check') })`. Within a minute the error shows in the `ancestors-tree-web` project, with the commit as its release. Errors typed straight into the console are not reported; the `setTimeout` makes this one a real unhandled error.
4. **Source maps.** In the `ancestors-tree-web` project, **Settings → Source Maps** lists an artifact bundle for the release. `curl -I https://ancestorstree.netlify.app/assets/<the index-….js file name>.map` answers 404: the maps were deleted before publishing.
5. **Sentry, API.** The API reports only unexpected errors, and there is no route that fails on purpose. To check the DSN, run this once from `apps/api` on your own machine. It sends one test message; a DSN only allows sending events, but keep it out of shared shell history anyway:

   ```bash
   SENTRY_DSN='<your DSN from Sentry → Project settings → Client Keys>' node --input-type=module -e "import * as Sentry from '@sentry/node'; Sentry.init({ dsn: process.env.SENTRY_DSN }); Sentry.captureMessage('P8 Sentry check'); await Sentry.flush(5000);"
   ```

   The message shows in `ancestors-tree-api`. From then on, real 500s arrive there with the commit as their release.
6. **Uptime monitor.** The existing UptimeRobot monitor calls `/api/health` every 5 minutes. That route is exempt from the signature check, so the monitor stays green and keeps the server awake. Check that it is still green after the deploy.
````
